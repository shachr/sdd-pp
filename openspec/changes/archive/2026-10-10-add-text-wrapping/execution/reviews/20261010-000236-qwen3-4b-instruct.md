- `src/text-wrapping.mjs:30-31` - The logic in `wrapParagraph` does not correctly handle the "Remainder shares its line" scenario as specified in the spec. When a word is split, the remainder is not preserved in a way that allows subsequent words to join it. For example, in `wrapText("abcdefghij x", 4)`, the code produces `["abcd", "efgh", "ij x"]`, which matches the expected output, but this is due to a coincidence of the test case, not correct general behavior. The current implementation only splits the word and then immediately starts a new line, without preserving the remainder for potential joining with subsequent words. This violates the requirement that "the last piece becomes the current Line" and that "later words may join its line when they fit". The test case "Remainder shares its line" is present in the test file, but the underlying logic fails to implement the requirement correctly. The requirement explicitly states that "the last piece becomes the current Line" and that "later words may join its line when they fit", which is not implemented in the current code. The current code in `wrapParagraph` only checks if the current line can fit the next word, and if not, it starts a new line. It does not preserve the remainder of a split word for potential joining with subsequent words. This is a critical failure of the implementation.
