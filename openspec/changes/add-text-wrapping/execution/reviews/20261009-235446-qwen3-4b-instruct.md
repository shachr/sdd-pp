## 📌 Key Changes by File

### 1. `checkChange.mjs` – Enforce Requirements Integrity

#### ✅ What Changed:
- Removed strict enforcement of forbidden sections (like "User Stories", "Problem Statement") that restate behavior.
- Introduced a **new `advisory` list** that only triggers **warnings** (not errors) when `config.strictDuplication === false`.
- Now warns about sections that **do not link to the proposal or delta**, even if the section is technically allowed.

#### 💡 Why?
- Previously, any section like "User Stories" was blocked — too rigid.
- Now, such sections are **allowed if they link to the source of truth** (proposal or delta), which supports better flexibility and clarity in design.
- This aligns with the principle: *“Requirements live only in the delta”* — meaning only the delta (proposal + specs) is authoritative.

> 🚨 **Note**: If `config.strictDuplication` is enabled, then **all restatements are treated as errors** — useful for strict compliance or audit.

#### 🔍 Example:
```js
// Before:
if (forbidden) errors.push(...);

// After:
const advisory = config.strictDuplication ? errors : warnings;
for (const s of restatingSections(text)) {
  advisory.push(`... section has no link to proposal/delta`);
}
```

### 3. `change.mjs` – New `restatingSections()` Function

#### ✅ What Added:
- A new function that parses Markdown to detect sections that:
  - Match forbidden headings (e.g., User Stories, Requirements)
  - Lack links to `proposal.md` or `specs/*.md`

#### 🔍 How It Works:
- Splits the document into lines.
- Finds section headers using regex.
- Identifies the body of each section.
- Checks if the body contains a link to `proposal.md` or a delta spec.

> ⚠️ If no such link exists → warning issued.

#### Example Output:

## 🚩 Potential Risks / Caveats

1. **Misuse of "allowed" sections**  
   → If a section like "User Stories" is used without linking to the source, it may be misinterpreted as a re-statement.  
   ✅ **Fix**: Enforce link checks via `restatingSections()`.

2. **Over-reliance on AI-generated content**  
   → AI may generate paraphrased content. The tool now warns, but doesn’t prevent it.  
   ✅ **Mitigation**: Use `strictDuplication` mode in high-stakes projects.

3. **Tooling assumptions**  
   → Assumes all changes have `proposal.md` and `specs/**/spec.md`.  
   ✅ **Guardrails**: Add validation in `checkChange()` to ensure these files exist.

## ✅ Recommendations

1. **Add a config flag** like `strictDuplication: true` to enforce zero paraphrasing in critical projects.
2. **Integrate with linting tools** (e.g., ESLint, Prettier) to catch violations in CI.
3. **Add a "review checklist"** in the docs for reviewers to verify:
   - All sections link to proposal/delta
   - No paraphrasing or restating
   - All design decisions are in `execution/design.md`
4. **Add unit tests** for `restatingSections()` with edge cases (e.g., empty bodies, nested sections).
