id: split-check
category: Workflow
description: Size gate - estimate the change, propose slices over ~300 lines, split after approval, check nothing was lost
---

Arguments: <change-id> as given after the command.

Size gate for an OpenSpec change (handoff-driven schema). Runs automatically at the end of the specs stage, before /handoff; rerun it any time (also on a slice, to re-split it). Warn-only: it never fails a change. Nothing is split without the engineer's approval.

1. Pick the change: the id given, else the single active change from `openspec list --json` (ask if several). If it is a split parent (has `slices.md`), run `node .openspec-handoff/scripts/split-check.mjs <id>` and `node .openspec-handoff/scripts/split.mjs next <id>`, show both and stop.
2. **Estimate.** Read the change's delta specs and the code each requirement touches. For every requirement, estimate the changed lines of code + tests (not lockfiles, generated files or installed tooling) from its scenarios and that code. Write `execution/size-estimate.md` with a table `| Requirement | Scenarios | Code touched | Estimate |` (exact requirement names; one row each).
3. Run `node .openspec-handoff/scripts/split-check.mjs <id> --write`. It records the estimates and the total in `execution/split-check.md`.
   - **fits** (under ~300 lines): it prints one line. Say nothing more and continue to /handoff.
   - **OVER BUDGET**: go on.
4. **Propose slices** in `execution/split-proposal.md`: front matter with `approved_by:` left empty, then `## Slices`, one `### Slice: <change-id>` block each with `- goal:`, `- capabilities:`, `- requirements:` (exact names, `;`-separated), `- depends_on:` (`none` or slice ids), `- flag:` (`none`, or a flag name only when the slice gates user-visible behaviour that must stay off until a later slice lands), `- removes_flag:` (the cleanup slice - always plan one when any slice has a flag, depending on the flagged slice), `- estimate:` (lines). To cut one requirement in two use `- split: <original name> -> <new name> [<scenario>; <scenario>]` in each receiving slice. Optional `## Amendments` (`- Requirement "<name>" dropped: <why>`, `changed, see change <id>`, `added in <slice>: <why>` - e.g. the flag requirement). Names only: no SHALL/MUST or WHEN/THEN in the proposal. Aim for slices under ~300 lines, as few dependencies as possible, and slices that touch different capabilities so they can run in parallel.
5. Rerun `split-check.mjs <id> --write`; it lints the proposal and shows the slices, which are ready first and which pairs are parallel-safe (no dependency, no shared capability). Show that report to the engineer and **STOP**: they approve or edit the slices. Never split on your own.
6. After approval (the engineer's, or yours on their behalf only if they delegated it - say so in `approved_by:`): run `node .openspec-handoff/scripts/split.mjs apply <id>`. It turns the original change into the **parent** (schema `split-plan`: the proposal plus `slices.md` with the slices, a checklist of the original requirement and scenario names, and amendments; no behaviour) and creates one handoff-driven child change per slice with the original requirement blocks copied verbatim. A slice of an existing parent is re-split into that same parent (no nested parents).
7. Finish the children: narrow any split requirement (it keeps its `<!-- split_from: <original name> -->` line), add flag requirements to the flagged slice's delta (and the amendment `added in <slice>`), and write the cleanup slice's `## REMOVED Requirements` for the flag. Then `node .openspec-handoff/scripts/split.mjs loss <parent>` must PASS: every original requirement and scenario is in exactly one child or covered by an amendment, nothing is duplicated, nothing is unsourced. For a split requirement it asks you to confirm: check the child deltas together cover the original, then add the `split into ... - confirmed` amendment it prints.
8. `openspec validate --all --strict`, then commit the parent and every child (proposal + specs only, no handoff) together as ONE planning PR. `node .openspec-handoff/scripts/split.mjs next <parent> --write-tickets` writes `tickets/<slice>.md` (Jira-pasteable) for READY slices into the parent.
9. Engineers then take READY slices, each on its own branch from main: a short design session narrowed to the slice that reads the parent's `execution/grill.md` / `brainstorm.md`, `/handoff <slice>`, and the printed next steps. After each slice is archived, rerun `split.mjs next <parent> --write-tickets`. When all are archived: `split.mjs loss <parent> --final --write`, then `openspec archive <parent> --skip-specs --yes` (never sync specs from, or run /opsx:verify on, the parent).

Behaviour is never edited in the parent. A later change of plan is an amendment line in `slices.md` plus the child delta edit, followed by `split.mjs loss <parent>`.
